# Provider credential echo containment (incomplete)

Do not activate desktop real-key generation on the basis of this guard. It is defense in depth, not a complete secret-leak boundary.

For providers constructed by `createProviders`, successful search hits, extracted pages, and completed LLM result objects are scanned before the pipeline receives them. The configured Anthropic, OpenAI, Tavily, Brave, Azure Speech, ElevenLabs, and Fish Audio keys are compared against strings and object keys using exact, URL-component encoded, base64 (padded or unpadded), and base64url representations. Comparison is case-insensitive to cover percent-escape case; this can produce false positives, especially with short credentials. Matches or scanning failures stop the call with the fixed warning `Provider output blocked: possible credential exposure`. Normal results pass through unchanged.

This scans provider-returned values, **not raw HTTP bodies or all streams before provider-internal handling**. Search adapters normalize and discard fields, extractors truncate/transform content, and the AI SDK can parse or retry internally before the guard sees its completed object. ChatGPT selection can replace the guarded LLM, and OAuth credentials, externally supplied custom providers and separately constructed providers are not covered. TTS audio/files, existing caches/artifacts, user inputs, provider-internal logs, arbitrary encoded/fragmented/transformed secrets, and output already written by a provider are not inspected. Streaming is only inspected after the selected provider resolves its completed object; deferred/internal sinks are not fenced. Usage accounting for a blocked response may also be incomplete. Guarding before every such sink and testing publication and failure paths remains necessary before real keys can be enabled. Never assume this can detect every transformation.

Smoke diagnostics deliberately print only fixed status, allowlisted provider labels, and result counts; they do not print configured endpoints, models, voice names, paths, returned objects, usage, or search content. This does not prevent a provider itself from writing a file (e.g. TTS output).
