# Provider credential echo containment (incomplete)

This guard is defense in depth, not a complete secret-leak boundary. Desktop key activation (see `apps/desktop/D5-KEY-ACTIVATION.md`) does not rely on it as the boundary: it relies on passing only usable keys, fixed provider endpoints and fixed error text.

For providers constructed by `createProviders`, successful search hits, extracted pages, and completed LLM result objects are scanned before the pipeline receives them. The configured Anthropic, OpenAI, Google, Tavily, Brave, Azure Speech, ElevenLabs, and Fish Audio keys are compared against strings and object keys using exact, URL-component encoded, base64 (padded or unpadded), and base64url representations. Comparison is case-insensitive to cover percent-escape case; this can produce false positives, especially with short credentials. Matches or scanning failures stop the call with the fixed warning `Provider output blocked: possible credential exposure`. When at least one key is configured, a result that passes is returned as a plain copy built from exactly the values that were scanned, each property read once, so a getter or proxy cannot present a different value later. Results that are not plain data (class instances, functions, cycles or shared references) cannot be copied faithfully and are blocked. With no key configured, results pass through untouched.

This scans provider-returned values, **not raw HTTP bodies or all streams before provider-internal handling**. Search adapters normalize and discard fields, extractors truncate/transform content, and the AI SDK can parse or retry internally before the guard sees its completed object. ChatGPT selection can replace the guarded LLM, and OAuth credentials, externally supplied custom providers and separately constructed providers are not covered. TTS audio/files, existing caches/artifacts, user inputs, provider-internal logs, arbitrary encoded/fragmented/transformed secrets, and output already written by a provider are not inspected. Streaming is only inspected after the selected provider resolves its completed object; deferred/internal sinks are not fenced. A blocked LLM response was still billed: its usage is recorded when it is valid (provider and model reduced to known labels), and usage that is present but not trustworthy is recorded as unreconciled spend, which stops the budget guard until it is reconciled. Usage of blocked search results is not tracked, as search usage is not tracked at all. The guard does not promise detection of arbitrary transformations.

Smoke diagnostics deliberately print only fixed status, allowlisted provider labels, and result counts; they do not print configured endpoints, models, voice names, paths, returned objects, usage, or search content. This does not prevent a provider itself from writing a file (e.g. TTS output).
