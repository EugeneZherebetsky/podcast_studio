# ChatGPT plan: experimental sign-in

Settings supports experimental sign-in when the server listens on numeric loopback and Settings is opened directly at that address (not via a proxy or Vite). Choose a label, start sign-in, then open the OpenAI link; cancel or sign out in Settings. Script generation is not connected to this session and the configured provider is unchanged. Sign out before exiting: shutdown clears credentials locally without confirming remote revocation. If revocation fails, disconnect the app in ChatGPT Settings.

An experimental local CLI provides a separate sign-in and text inference session. Run `pnpm --filter server chatgpt`, then enter `login <label>` and open the displayed URL in a system browser; use `models` to list eligible models and `ask <model> <prompt>` to generate text. Results are shown only after completion, limited to 1 MB of stream data and 60 seconds; Ctrl-C cancels an active request. Use `status`, `signout`, and `quit` in the same process. Use a different label for another registration. Sign out before changing accounts. Only a stable opaque host ID and verified account/client mappings are stored under `DATA_DIR/chatgpt`; configure DATA_DIR on private storage (the default `data/` is git-ignored). On Unix the new files use owner-only modes; on Windows they inherit the directory ACL, which the user must keep private. A stale `chatgpt-registration.lock` after a crash must be removed manually only after confirming no CLI is using it. Tokens remain in process memory; exiting loses the session and does not revoke it. Signout attempts remote revocation and warns if it could not confirm it. No tokens are sent to the browser. Local Ollama remains unchanged; there is no paid API fallback.

OpenAI documents [ChatGPT plan usage for locally hosted open-source apps](https://developers.openai.com/siwc/token-sharing-open-source), including [registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), and [UX](https://developers.openai.com/siwc/ui-ux-guidelines). The isolated login uses fresh state, nonce and S256 PKCE, bounds the listener and exchange, and verifies RS256 signatures and identity claims with `jose` and OpenAI's JWKS. Granted token-response scopes determine plan permission; a verified identity alone is insufficient.

## Experimental script draft

In the same CLI session, use `models`, then `script <model-slug> <research.json>`. The UTF-8 JSON file contains `{ "mode": "standard", "lang": "en", "plan": {...}, "notes": {...}, "sources": {...} }`, using the existing pipeline's `PlanSchema`, `NotesSchema`, and `SourcesSchema` (`apps/server/src/pipeline/schemas.ts`). Prepare these research artifacts separately; this command does not search the web. It sends the plan and notes to ChatGPT and prints a validated script with `reviewed: false`; it does not modify the input or write an episode. Review the result and its sources before use. Factual support is not established by schema validation. Review, TTS, publishing, retries and pipeline caching are not connected.

The command requests JSON schema output and validates the completed response locally, including citation IDs and word budget. Plan inference documentation does not establish structured-output compatibility; if the service rejects this request the command fails rather than falling back to unstructured text or a paid API. No live compatibility test has been performed. Input research is sent to OpenAI only when the user runs this command.

Before pipeline generation integration: review authorization to send data and shared config/schema changes; implement refresh serialization and more resilient revocation. Never expose credentials or PKCE verifiers to browser-accessible APIs or logs. Request/response size and time bounds, cancellation, local process threats, and callback origin/Host handling require continuing security review.

Windows credential protection is unresolved. Node's Unix mode bits alone do not establish a private Windows ACL. Evaluate OS-backed storage such as [Windows Credential Manager or DPAPI](https://learn.microsoft.com/en-us/windows/win32/secbp/threat-mitigation-techniques); any new native dependency requires separate approval. Do not persist tokens in plaintext as a workaround.

The existing pipeline requires Zod-validated structured objects and retry/usage accounting. OpenAI's plan-usage docs require streaming Responses with `store: false`, `stream: true`, and `response.completed`; several normal Responses parameters are unsupported. The plan-specific documentation reviewed does not establish structured-output support for this route, so that compatibility must be verified without assuming ordinary API behavior. Discover account-eligible models rather than hardcoding them. Enforce size/time limits, validation and no tool access to untrusted sources. Implement plan-limit messaging and usage links per OpenAI's UX requirements, without automatic paid fallback. No live login or inference has been performed.
