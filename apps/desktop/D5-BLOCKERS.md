# D5 remains disabled

The desktop tray exposes an **inactive prototype** for synthetic test values only. Stored values are never read into the desktop child; changes never restart the server. The desktop child ignores its home `.env`, with no fallback. Do not use real credentials until the remaining gates are resolved.

- Before activation, review only the built-in provider implementations and enforce their fixed HTTPS endpoints for every credential-bearing request. A selected provider necessarily receives its key and must be trusted. This does not protect against same-user malware or guarantee detection of arbitrary encoded, fragmented, transformed, or provider-written echoes. The existing result scanner is defense in depth, not the trust boundary.
- Normal provider errors and logs must remain secret-free; exercise success, error, timeout and cancellation with synthetic credentials through the real dispatch path, inspecting SQLite, artifacts, events, HTTP, SSE and CLI output. The current synthetic generation test covers one exception and selected sinks only. The scanner reads object properties via getters and returns the original object, so a later read can differ from the scanned value. A blocked paid LLM result can also lose its usage record; preserve valid cost information or fail closed on uncertain spend before activation.
- A key change must not restart or interrupt an active or uncertain job. Activation must occur only on the next manual application launch after the user has confirmed no job is active.
- The Windows-only encrypted store serializes cooperative updates using a lock directory. A crash may leave a lock requiring manual recovery after confirming no owner is running. It rejects corrupt stores, oversized ciphertext, symlinks and junctions, and uses a flushed temporary file followed by rename. Path checks do not prevent same-user races; DPAPI does not isolate other processes running as the same Windows user. Power-loss durability is not established. Do not automatically remove stale locks.
- The dedicated sandboxed local file window validates IPC sender and frame and exposes only presence/set/clear. Review Electron's file protocol guidance, session permissions and packaged integrity before real credential use. Never store ChatGPT session tokens.
- Windows symlink creation may require privileges; exercise it on a suitably configured system. Test installed packaging and the actual shell with a separate profile before enabling activation.
